# Yoyoo 首页体验评估

Method: dual-agent (A: /root/experience_design_review · B: /root/experience_evidence_scan)

## 结论

当前首页已经摆脱了廉价 dashboard 和堆卡片感，单焦点构图、雨夜空间、玻璃输入区已经成立。与参考图相比，氛围接近，但产品含义、Live 真实性和状态连续性仍弱。首页主体不属于 AI-slop；高饱和青紫 Live 球和通用雨夜赛博城市仍有明显模板感。

## 评分

- 氛围与空间：8.2/10
- 构图与层级：8.0/10
- UI 材质与细节：7.2/10
- Text/Live 连续性：5.8/10
- 产品可信度：5.5/10
- 综合：7.0/10

## 优点

1. 问候、状态、输入框形成唯一主路径，认知负担低。
2. 背景压暗、顶部高光、描边和 blur 形成可信玻璃层次。
3. 桌面和移动端均无溢出，44px 控件、安全间距和响应式布局可靠。
4. loading、error、ready、Live、muted 状态都有结构基础。

## 优先问题

- P0：Live 直接显示“正在聆听”，但没有麦克风授权、连接、失败或恢复阶段，产品状态不真实。
- P1：Home 的灰蓝、薄荷色语言与 Live 的亮青紫球割裂，Live 看起来像通用语音助手 demo。
- P1：进入 Live 时整块替换主画布，没有从语音按钮到 Orb 的共享锚点和阶段反馈，容器连续但情绪不连续。
- P2：雨城解释了情绪，没有解释 Yoyoo 的协作能力；缺少一个克制但真实的产品专属信号。
- P2：10.24px 状态文字和 58% 不激活图标叠在动态背景上，存在弱对比风险。
- P2：移动端裁切后城市结构变弱，主要剩暗雾和水面，品牌氛围下降。

## 与参考图的差距

参考图的背景直接表达天气任务，三组不同尺度的信息形成不对称平衡，所有玻璃层都承载有效状态。Yoyoo 已经继承了完整空间、可信材质和低认知负担，但背景目前只承担气氛，中心窄轴缺少反向支点。无需复制参考图的信息密度，应让少量界面状态与空间产生因果关系。

## 体验实测

- 桌面 1440x900：无滚动和截断；主内容相对屏幕中心右移 32px，与 64px 侧栏补偿一致。
- 移动 390x844：首页和 Live 均无溢出；Live 控制条距底栏 23px，无重叠。
- 桌面 Orb 168px，移动 Orb 136px，尺寸合理；问题在视觉语言而非大小。
- detector CLI 0 命中；浏览器检测的 overflow 为背景主动放大导致的误报，green glow 仅为风格警示。
- 控制台 0 warning；唯一错误是开发态 icon 资源空响应。

## 人群风险

- 熟练用户：文字和 Live 缺少取消、连接状态、快捷退出与恢复机制。
- 首次用户：图标导航和语音入口含义需要猜测，Yoyoo 能做什么不够可识别。
- 移动用户：触控尺寸合格，但底栏无文字、状态字偏小，系统中断后状态不持久。

## 下一轮验证重点

1. Live 权限与连接状态是否真实可见并可恢复。
2. Home 到 Live 是否是一段连续转场，而不是切换页面。
3. Orb 是否融入雨城的低饱和冰青色，而非独立青紫 demo。
4. 是否出现一个只有 Yoyoo 才有、且能参与交互的产品信号。
