# 007 Feature: 对话底座

> Date: 2026-08-06

## 背景

视觉首页已经形成稳定基线，但页面仍只能展示本地消息。真实对话开发的第
一个切片不是直接绑定 YOS，而是先建立 Yoyoo 自己拥有的通用 Agent 边界和
可持久化的数据约束，使后续的 YOS、测试 Agent 或其他 Agent 都使用同一套
平台语义。

## 本次范围

- 通用 `AgentAdapter`：描述、健康、运行事件和可选取消能力。
- 严格运行时校验：共享契约不允许混入厂商专属字段。
- 确定性测试 Agent：可控制分片、延迟、失败与中止。
- PostgreSQL 17 本地服务、前向迁移和迁移校验和保护。
- `conversations`、`messages`、`runs`、`run_events` 四张业务表。
- 独立的数据库集成测试配置和命令。

## 关键决策

1. **先测试 Agent，再接 YOS。** 当前尚未确认 YOS 稳定的对话入口、认证、
   流式事件与取消语义。先用确定性实现验证平台，避免把猜测固化进公共契约。
2. **数据库负责底线约束。** 状态、空内容、幂等键、外键、终态时间和事件
   序号不仅由应用约定，也由 PostgreSQL 拒绝非法写入。
3. **已应用迁移不可改写。** 迁移器保存 SHA-256 校验和；同版本内容变化会
   直接失败。advisory lock 防止并发迁移。
4. **不提供隐式清库能力。** Compose 使用持久卷
   `yoyoo_space_pg_data`，只提供启动、迁移和状态查看命令。

## 依赖

- `pg@8.22.0`：直接、参数化的 PostgreSQL 驱动。
- `@types/pg@8.20.0`：`pg` 的 TypeScript 类型。
- `zod@4.4.3`：Agent 边界的运行时结构校验。

版本均精确锁定在 `package-lock.json`。本次安装使用本机 npm 缓存，未访问
外部注册表。

## 否掉的备选

- **直接实现 YOSAdapter：** 缺少已确认的真实协议证据，容易把内部实现误当
  公共 API，因此推迟到独立协议核验后。
- **使用内存或 SQLite：** 无法覆盖既定的服务重启、并发写入、事件游标和
  长期自托管目标。
- **自动重建测试数据库：** 虽然方便，但会引入隐式破坏性行为；当前测试用
  随机标识隔离数据，不删除表或卷。

## 验证结果

- Agent 契约按 TDD 先出现缺失模块失败，随后 5/5 测试通过。
- PostgreSQL 测试按 TDD 先出现缺失客户端失败，随后 3/3 集成测试通过。
- `npm run lint`：通过。
- `npm run typecheck`：通过。
- `npm test`：3 个测试文件、11 个测试通过。
- `npm run test:integration`：1 个测试文件、3 个测试通过。
- `npm run build`：Next.js 生产构建通过，公开路由保持为首页、图标和
  `/orb-preview`。
- `npm run test:e2e`：桌面与移动端共 10/10 浏览器测试通过，未引入视觉
  回归。
- PostgreSQL 容器：`healthy`，仅监听 `127.0.0.1:55432`。
