# Agent 生产链路稳定性收口

## 背景

V0.20 上线后，使用本机 YOS `0.1.18` 和真实 Owner 登录态完成生产全链路验收。
链路已经证明 Agent 可以认领邀请、获得唯一 AI Card、进入精确房间、回复消息、
重启后复用同一身份，并在 Owner 撤销后失去 Yoyoo 连接权限。

验收也暴露了三个稳定性问题：撤销后的网关会继续重试认证；Web Console 中一条
已经失败的旧入站消息会长期阻塞后续任务；活动监控重建 Codex 时可能继承
`TERM=dumb` 并停在人工确认提示。

## 关键决策

- HTTP `401` 或 `AGENT_UNAUTHENTICATED` 是授权终止，不是普通网络抖动。网关上报
  一次安全错误后立即退出，等待重新授权或人工重启，不持续请求生产服务。
- YOS Web Console 没有返回消息状态，因此只在上游提供的消息时间戳已经超过本轮
  回复窗口时，才把旧入站消息视为遗留失败并开始新任务。缺少或无法解析时间戳时
  保持原来的保守等待行为。
- 终端类型写入本机 YOS 的私有配置，由会话构建逻辑显式传给新 tmux 会话，不依赖
  PM2 当前进程偶然继承的环境。

## 没有选择的方案

- 不让撤销后的网关无限退避重试。撤销只有重新授权才能恢复，持续重试只会制造
  日志和无效请求。
- 不直接修改 YOS SQLite 状态，也不清空历史消息。Yoyoo 只依据公开 Web Console
  契约处理可确认的陈旧请求，避免跨过系统边界改上游数据。
- 不把所有未回复入站都直接跳过。仍在正常回复窗口内的上一条任务必须先完成，
  否则可能把两个回复错误关联到同一通道。

## 验证结果

- 生产真实链路：YOS 获得 `AI_100002`，在授权房间返回指定验收文本；停止并重启
  网关后仍复用同一 Card；本机 YOS 冷启动后可继续运行；撤销后生产接口立即返回
  `AGENT_UNAUTHENTICATED`，设置页显示已撤销、不可连接。
- 定向回归：`tests/agents/yos-adapter.test.ts` 8/8 通过。
- 定向集成：`tests/integration/agent-gateway-client.test.ts` 11/11 通过。
- 完整门禁：lint、typecheck、生产构建通过；常规测试 47 个文件、208/208
  通过；PostgreSQL 集成测试 25 个文件、139 项通过，另有 5 个文件、7 项按
  环境门禁跳过。
- 终端冷启动：即使 PM2 进程被刻意设为 `TERM=dumb`，删除 `codex-main` 后监控重建
  的 tmux 会话仍为 `TERM=xterm-256color`，未出现人工确认阻塞。
