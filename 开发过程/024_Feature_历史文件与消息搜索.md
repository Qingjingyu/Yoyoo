# 024 Feature - 历史文件与消息搜索

> 日期：2026-08-10
> 范围：IM-1 第 4 阶段

## 背景

IM 的文件与消息在刷新后必须可找回，但搜索不能先查全局结果再由 UI 隐藏，否则总数、摘要和文件名都会泄露。

## 关键决策

- PostgreSQL 在权限 JOIN 后再匹配消息文字或附件文件名，并提供有界分页和确定排序。
- 支持房间、发送者、资源类型与日期过滤；文档正文、OCR 和向量检索留到后续。
- 搜索结果回到权威来源房间并聚焦原消息，不复制一份不可追溯的内容。
- 房间详情栏按图片、文档、归档和 Agent 产物展示历史文件。
- 撤回消息及其附件不出现在普通搜索、文件库或下载路径中，审计事实仍保留。

## 否掉的备选

- 前端下载全部消息后过滤：性能差且扩大泄露面。
- 独立文件管理首页：不是当前高频一级入口，也会破坏已确认首页。
- V0.9 直接上全文抽取与向量库：超出最小日用闭环。

## 验证结果

- Repository/HTTP 测试覆盖文字、文件名、全部过滤器、分页、归档房间、移除成员和跨工作区拒绝。
- UI/Playwright `im-search.spec.ts` 覆盖空态、结果、来源导航、返回房间及窄屏布局。
- 搜索总数和摘要在授权过滤后产生。

## 未包含

- 文档正文、OCR、语义检索、跨工作区知识库和外部云盘索引不在 V0.9。
