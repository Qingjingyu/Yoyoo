# 029 Feature: 旗舰对话界面

日期：2026-08-11

## 背景

V0.11 已完成无背景的深浅双主题，但对话页仍存在三类质感问题：操作信息字号过小、不同区域材质层级不清，以及普通内容与状态反馈都在争夺青色强调。结果是功能完整，却不像一套安静、精密、可长期使用的未来协作界面。

## 本次范围

- 只打磨 `/conversation` 和它使用的共享视觉令牌。
- 保留全局导航、会话列表、房间头部、消息时间线、底部输入框和右侧详情栏的既有结构。
- 不改数据库、API、AI Card、Agent Gateway、房间权限、消息协议或首页信息架构。

## 关键决策

1. 未来感来自秩序和反馈，不来自背景图、HUD 网格或持续发光。
2. 建立会话侧栏、头部、时间线、人物消息、Agent 消息、输入框和菜单的语义材质，深浅主题共用同一组件结构。
3. 正文和输入文字保持至少 14px，操作元数据保持至少 11px，解决“看起来像缩小后的后台系统”的问题。
4. 当前会话采用完整选中面，而不是左侧彩色竖线；颜色、边框和文字共同表达状态。
5. 青色仅服务于选中、焦点、在线、运行和成功等语义状态；普通消息不使用状态色边框。
6. 只有正在运行的 Agent 状态点缓慢呼吸；上传进度使用 `transform`，并为减少动态偏好关闭动画。

## 否掉的方案

- 增加城市背景、装饰性光斑或数据网格：会再次让内容依赖场景图，并削弱双主题一致性。
- 给所有面板增加玻璃模糊和大面积阴影：信息密集时会产生廉价的叠卡感，也增加渲染成本。
- 全面改写对话 DOM：本轮目标是视觉基准，不应让已经验收的 IM 行为重新承担回归风险。
- 给普通用户消息保留青色描边：普通内容不是状态，强调色应留给真正需要注意的反馈。

## 代码改动

- `src/styles/tokens.css`：新增对话材质、字号、边缘和紧凑阴影令牌。
- `src/styles/conversation.css`：统一侧栏、消息、系统事件、附件、输入框、搜索和详情栏的视觉层级及响应式表现。
- `src/components/conversation/attachment-composer.tsx`：上传进度改为 CSS 比例变量，避免动画布局属性。
- `tests/ui/attachment-composer.test.tsx`：锁定 transform-ready 上传进度契约。
- `e2e/theme.spec.ts`：锁定字号下限、完整会话选中面和无彩色侧条规则。
