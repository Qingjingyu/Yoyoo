# 016 Feature 房间详情与成员管理

> 版本：V0.7
> 日期：2026-08-08

## 背景

V0.6 的房间管理使用局部菜单，无法承载长期的人类 + AI 成员管理。V0.7 将它收敛为标准 IM 三栏结构：房间列表、对话、按需打开的房间详情。

## 关键决策

- `…` 直接打开房间详情，不再使用中间弹窗或悬浮菜单。
- 成员管理位于详情页顶部，人类与 AI 使用同一份 Principal 列表。
- 当前版本只能从同一工作空间的已激活 Principal 中添加；不做邀请、注册和 AI 接入向导。
- 只有房间所有者可以增删成员；所有者不能被移除。
- 有 `queued` / `running` / `waiting` 运行的 AI 不能被移除，API 返回可见冲突。
- 移除只改变 membership 状态；历史消息、作者归属和 Artifact 都保留。重新添加复用原成员记录。
- 房间允许没有 AI，输入区会明确告知当前无可路由 Agent。
- 桌面宽屏使用 320px 固定第三栏，紧凑桌面覆盖主区，手机端使用全宽详情页。

## 否掉的备选

- 继续扩展小弹窗：容量不足，移动端容易溢出，不适合后续权限与资源设置。
- 把成员管理常驻在一级页面：它是低频管理行为，会挤压高频对话空间。
- 为成员变更新增数据表：现有 `room_memberships.status` 已能表达可逆移除，没有为同一语义增加 migration。

## 影响范围

- 新增房间成员 GET / POST / DELETE API 与对应客户端。
- 更新 PostgreSQL 仓储、协作服务、对话页和响应式样式。
- 首页、Agent 适配器协议、数据库 schema 和依赖均未变更。
