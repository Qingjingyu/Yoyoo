# Feature 032：公网单用户身份与部署

> 日期：2026-08-12
>
> 状态：已部署并完成公网验收

## 背景

V0.14 只能在 `127.0.0.1` 使用，并通过服务器环境变量把所有浏览器请求视为本机
所有者。直接发布会让匿名访问者继承所有者权限。V0.15 的目标是让唯一所有者可从
桌面和手机安全登录，同时保留现有房间、消息、文件和 Agent 身份。

## 关键决策

- 给人和 Agent 统一分配永久 AI Card ID，从 `AI_100001` 递增；所有内部授权、
  外键和消息归属继续使用不可变 Principal UUID。
- 第一版只允许 `AI_100001` 登录，不提供注册或邀请。ID 是公开地址，不是密钥。
- 密码使用 Node `scrypt` 加盐哈希；浏览器只持有 HttpOnly、SameSite 会话 Cookie，
  PostgreSQL 只存会话 Token 的哈希。
- 密码重置递增凭据版本并撤销旧会话；登录失败按账号和来源双重限流。
- 浏览器页面和 API 统一通过 Next.js Proxy 拦截；Agent Gateway 继续使用独立 Bearer
  凭据，不与人类会话混用。
- 生产包支持独立主机 Caddy，也支持现有 Nginx 主机只向回环地址暴露 Next.js；
  PostgreSQL 保持私网，BlobStore 使用持久卷。SQL 迁移只前进，应用回滚只切换
  已记录的旧镜像。

## 否掉的方案

- GitHub OAuth：手机端不够方便，且首版单所有者不需要外部账号依赖。
- 邮箱或短信验证码：过早引入供应商、费用和新的故障面。
- 把 AI Card ID 当秘密：顺序 ID 可枚举，只能用来寻址和登录名展示。
- 纯签名长效 Cookie：无法满足立即撤销和凭据轮换后的全会话失效。

## 实现说明

- 迁移 `013` 增加 AI Card ID、凭据、会话和限流表；已经应用的迁移保持字节级不变。
- 开发过程中发现共享开发库已经应用 `013` 后仍需调整首个所有者编号，因此没有改写
  已应用迁移，而是新增 forward migration `014` 保障冷启动所有者获得 `AI_100001`。
- `auth:bootstrap-owner` 幂等创建初始所有者和工作空间；`auth:provision-owner` 在 TTY
  隐藏读取两次密码，并且只显示一次恢复码。
- `/api/health` 只有在账号模式下存在有效 `AI_100001` 人类凭据时才就绪。
- `infra/production` 提供 Compose、Caddy、环境变量样例、上线检查和镜像回滚步骤。

## 当前边界

- 当前公网运行确定性 Agent，适合验证账号、IM、房间、文件与界面流程；真实
  YOS/Codex 或其他 Agent Runtime 尚未完成公网接入验收。
- 开发库历史没有自动导入公网。若需要保留真实会话，必须先从归档卷识别真实数据，
  再做按 ID 的选择性迁移，不能把测试夹具整库恢复到公网。

## 2026-08-12：登录首屏安全热修

- 现象：公网登录页的客户端脚本尚未初始化时，用户提交表单会触发浏览器默认的
  `GET /login?loginHandle=...&password=...`，既无法正常登录，也会把密码写入地址栏、
  浏览器历史和访问日志。
- 根因：登录表单完全依赖 React `onSubmit` 拦截，但服务端首屏 HTML 没有安全的
  `method`、`action` 和初始化锁。
- 修复：服务端首屏禁用两个输入框和提交按钮，客户端完成 hydration 后才开放；
  表单同时声明 `POST /api/v1/auth/login` 作为失效保护，确保脚本异常时也不会把凭据
  拼入 URL。
- 未采用原生表单完整登录：现有 API 使用 JSON、同源校验和统一错误状态；为无脚本
  场景再增加一套表单编码、Cookie 与重定向路径会扩大认证面，而产品本身依赖脚本。
- 回归证据：新增服务端首屏测试，并完成红灯到绿灯验证；登录 UI 4 项、类型检查、
  ESLint 和生产构建通过。全量单元/UI 首次运行有 1 项既有触屏长按用例偶发失败，
  该用例随后独立复验通过，未把它计入本次登录修复的通过证据。
