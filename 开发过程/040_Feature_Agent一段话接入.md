# 040 Feature - Agent 一段话接入

## 背景

Yoyoo 已具备 AI Card 身份映射、精确 `room_id` 通信和 Agent 运行时，但用户
仍需理解身份邀请、平台授权、节点凭据和 Yoyoo 接入等多段协议。目标是让空间
所有者只做一次受控授权并复制一段完整文字，Agent 自动完成发卡或复用、入群、
上线和精确房间通信。

## 关键决策

- Yoyoo 只签发空间与房间权限，不签发 Card ID。AI Card 仍是唯一身份权威。
- 新 Agent 在成功认领时才原子创建 Card、控制关系和节点；未使用、过期、
  拒绝或撤销的邀请不消耗编号。
- 已有 Agent 必须使用本机 `0600` 节点凭据证明身份并复用原 Card。为本次接入
  预建但未使用的新身份邀请会显式拒绝，避免产生第二张 Card。
- 所有发送、成员关系和撤销使用 AI Card Subject、Yoyoo Principal UUID 和
  `room_id`；名称只用于展示。
- 人类的 `agent.enroll` 只能创建或撤销受控邀请；Agent 的 `agent.runtime`
  只能运行，二者不能互相扩权。
- Yoyoo 撤销只关闭本地绑定、在线状态和后续访问，保留全局 AI Card 与历史归因。

## 否掉的备选

- 要求用户先去 AI Card 手动创建 Agent：步骤多且把内部身份边界暴露成第二个产品。
- Yoyoo 本地创建 Card：会产生第二发卡中心，破坏跨产品统一身份。
- 用昵称寻找 Agent 或房间：重名、改名和自动化场景都会误投递；必须使用 ID。
- 把长期 Token 放进复制文字：泄露面和撤销成本过大；本实现只传短期单次票据。

## 实现范围

- AI Card forward migration `0015`：延迟发卡、`agent.enroll`、展示名和机器名。
- Yoyoo forward migrations `020` 至 `022`：接入邀请、撤销状态和机器名。
- 设置页 `接入 Agent`：房间/最小权限选择、完整指令复制、待认领/在线/离线/
  过期/撤销状态，以及 Card ID 和机器名展示。
- Provider-neutral 参考客户端：标准输入读取票据、原子保存 `0600` 凭据、未知
  结果幂等恢复、已有 Card 复用、Yoyoo admission 和精确房间发现。
- 接入撤销同时关闭未认领 AI Card 邀请；已接入撤销关闭 Yoyoo Agent binding
  与在线状态，不删除身份或历史消息。

## 验证结果

- Yoyoo：`lint`、`typecheck`、生产构建通过；47 个单元/UI 文件共 205 项通过；
  25 个可运行集成文件共 138 项通过，5 个外部环境文件的 7 项按开关跳过；
  桌面/移动端 Playwright 38/38 通过。
- AI Card：`lint`、`typecheck`、生产构建通过；31 个单元文件共 103 项通过；
  12 个集成文件共 62 项通过；桌面/移动端 Playwright 32/32 通过。
- 迁移与接入定向回归：6 个文件、27 项通过；issuer/config 回归 3 个文件、
  18 项通过。
- 跨仓库联邦验收通过：人类注册、Yoyoo 创建邀请、新 Agent 获得 Card、节点
  认证、精确房间发现与发信、第二次接入复用同一 Card、数据库无重复身份。

## 影响与未完成项

- 新增的是本地实现和自测证据，没有修改生产数据库、反代、DNS 或容器。
- V0.19 仍是生产基线。V0.20 上线前必须单独完成备份、迁移预检、回滚准备、
  明确发布审批和真实生产 YOS 的接入/收发/重启/撤销冒烟。
- 尚未完成第三方独立安全审查，也不支持公共 Agent 市场或动态第三方客户端注册。
