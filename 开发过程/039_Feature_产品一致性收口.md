# 039 Feature - 产品一致性收口

## 背景

Yoyoo 的登录、AI Card 和多人多 AI 房间已经是真实能力，但界面仍残留
早期单用户原型假设：首页使用第二套 current-conversation 客户端、问候和
人工介入写死用户名字、我的 AI Card 跳到外部身份站、首页展示没有真实
音频传输的 Live 入口、全局错误页冒充首页、独立 Orb 研究页仍可公开访问。
这些问题单独看很小，组合起来会让用户无法判断自己正在使用同一个产品。

## 关键决策

- 浏览器消息统一通过 `room_id` 和现有 Room API 发送。首页只负责进入一个
  精确房间，不再维护第二份会话历史。
- 所有展示名称和操作归因读取当前工作空间 Principal；不从昵称文字推断
  身份，也不在界面写死 Owner 名字。
- `我的 AI Card` 读取现有 session projection，并在 Yoyoo 内部直接展示
  Card ID、昵称和 Handle。AI Card issuer 保持后端权威边界，不作为产品
  导航目的地。
- 首页在真实音频采集、传输和授权闭环完成前不提供麦克风或 Live 入口。
  Orb 组件源码和组件测试保留，公开研究路由在代理层返回真实 `404`。
- 根 loading/error 只显示通用 Yoyoo 状态，不假定当前路由是首页。
- 没有新增依赖、数据库迁移、生产数据修改或生产配置修改。

## 否掉的备选

- 只把 AI Card 外链改成弹窗：无法解决双会话、固定姓名和假语音入口，
  同类问题仍会继续出现。
- 保留首页 Live 并标注“即将上线”：用户仍会把可点击控件理解为可用功能。
- 删除 Orb 实现：未来真实语音仍需复用其状态视觉；关闭公开路由已经足够。
- 让首页自动创建新房间：会产生不可见的会话副作用；本轮复用服务端返回的
  现有规范房间，空房间则明确提示用户前往对话页创建。

## 改动范围

- 首页工作空间加载、动态问候、精确房间发送与继续入口。
- 首页输入框和旧 Live 入口。
- 设置页 AI Card 站内展示、身份错误重试与单一 AI 授权入口。
- 删除已无调用方的外部 AI Card 个人页地址生成器，避免后续重新接回外跳。
- 协作房间人工介入归因。
- 根 loading/error、Sidebar 中性状态和 Orb 路由代理边界。
- 对应单元/UI、代理、桌面与移动浏览器验收。

## 状态覆盖

- 首页：loading、workspace error、ready、无房间、发送失败和发送成功。
- 当前身份：loading、error + retry、ready + in-product Card dialog。
- AI 目录：loading、error + retry、empty、ready、授权结果和凭据操作失败。
- 全局路由：neutral loading、visible error + retry、retired preview 404。

## 测试结果

- `npm run lint`：通过。
- `npm run typecheck`：通过。
- `npm test`：44 个测试文件、196 项通过；已删除的 5 项只覆盖废弃外跳地址
  生成器，当前站内 Card 展示与代理 404 均有独立回归测试。
- `npm run test:integration`：24 个文件、134 项通过；5 个文件中的 7 项
  真实外部服务检查按环境开关跳过，未计为通过。
- `npm run build`：Next.js 16.3 生产构建通过。
- 第一次 Playwright 运行 28/38，通过项覆盖附件、搜索、房间和主题；10 项
  失败均来自旧的固定姓名或模拟 Live 验收。
- 第二次 Playwright 运行 36/38；剩余 2 项证明 Next 流式 404 返回了 HTTP
  200。代理层前置拒绝后，最终桌面与移动端 38/38 通过。

## 影响与未完成项

- 首页发送现在进入现有房间 IM，因此会产生真实、可持久化的房间消息。
- 旧 `/api/v1/conversations/current` 服务端兼容接口仍保留给集成回归和旧
  运行时，没有继续被首页浏览器调用；删除它需要独立迁移评审。
- 真实语音采集、传输、权限、转写和 Agent 实时回复仍未实现，界面不再伪装
  已有这些能力。
- V0.19 仅在本地完成验证，尚未提交、推送或部署。生产发布必须重新核验
  当前分支、备份、镜像、迁移基线、回滚目标和公网登录/消息流程。
