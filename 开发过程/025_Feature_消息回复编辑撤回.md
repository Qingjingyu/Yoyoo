# 025 Feature - 消息回复、编辑与撤回

> 日期：2026-08-10  
> 范围：IM-1 第 5 阶段

## 背景

房间此前已经持久化 `reply_to_message_id`，但没有完整引用体验，也没有消息修订与撤回语义。仅在前端隐藏内容会导致搜索、文件库、下载和 Agent 上下文继续暴露旧内容，因此本阶段以数据库可审计事实为核心完成整条链路。

## 关键决策

- 新增前向迁移 `010_message_revisions.sql`，不修改已应用迁移。
- `room_messages` 保存当前可见版本和单调递增版本号；`room_message_revisions` 追加保存创建、编辑、撤回事实。
- 撤回不物理删除消息、附件关系、运行和来源；普通房间、搜索、文件下载与未来 Agent 上下文统一过滤撤回内容。
- 只有当前人类发送者可修改普通已完成消息；归档房间、非人类消息、执行中消息和过期版本均拒绝。
- 相同编辑或撤回请求可安全重试；不同内容的过期写入返回稳定冲突。
- 回复、复制、编辑、撤回收进消息紧凑菜单；编辑在原消息内完成，撤回要求二次确认。

## 否掉的备选

- 物理删除消息：会破坏审计、回复来源、附件归属和运行来源。
- 只保存最终文本：无法解释修改历史，也不能可靠解决多窗口覆盖。
- 用弹窗编辑：脱离消息上下文且增加视觉层级，改用内联编辑。

## 影响范围

- 数据：消息版本、撤回状态、修订审计表。
- API：`PATCH/DELETE /api/v1/rooms/:roomId/messages/:messageId`。
- UI：回复引用与来源定位、复制、编辑、撤回、已编辑与已撤回状态。
- 权限：搜索、房间文件、附件下载/Agent grant、Agent 历史上下文不再读取撤回消息。

## 验证结果

- 迁移与集成：3 个文件、8 项测试通过。
- 组件与客户端：2 个文件、22 项测试通过。
- `npm run typecheck`、`npm run lint`、`npm run build` 通过。
- Playwright `im-message-actions.spec.ts`：桌面 `1440x900` 与移动 `390x844` 共 2 项通过，无横向溢出。
- 覆盖本人/他人、系统消息、归档房间、执行中、过期版本、同请求重试、审计保留、搜索更新、撤回内容从 Agent 上下文排除、附件关系保留和回复来源定位。
