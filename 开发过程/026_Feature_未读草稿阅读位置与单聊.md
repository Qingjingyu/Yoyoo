# 026 Feature - 未读、草稿、阅读位置与单聊

> 日期：2026-08-10  
> 范围：IM-1 第 6 阶段

## 背景

文件与消息能力齐全后，日常 IM 仍需要可恢复的阅读状态、房间草稿和稳定单聊。只保存在浏览器会在刷新、多窗口或切换房间时丢失。

## 关键决策

- 前向迁移 `011_im_member_state.sql` 为每个房间成员保存单调 read cursor、可移动 reading position 和修订化草稿。
- 旧成员回填到迁移时最新已完成消息，避免升级后把全部历史误标为未读。
- 草稿写入携带 expected revision；完全相同的重试幂等，不同内容的过期写入返回冲突。
- 发送前先保存当前草稿版本，只有该版本成功提交后才清空；失败和更新版本均保留。
- 单聊按 workspace 与有序 human/Agent 对唯一复用，仍使用现有消息、附件、run、搜索和详情能力。
- 归档房间不能继续发送或保存草稿；旧异步 run 刷新不能覆盖用户已切换到的新房间。

## 否掉的备选

- 草稿只放 localStorage：多窗口和服务端发送无法协调。
- 未读只按时间比较：同时间消息和重试无法确定排序。
- 为单聊另建一套消息系统：会重复权限、附件与 Agent 执行逻辑。

## 验证结果

- `member-state-http.test.ts` 4/4：未读与单调阅读、草稿版本/重试/发送清理、稳定单聊、归档失败保留。
- `collaboration-room.test.tsx` 19/19：草稿恢复、强制保存、直接房间、未读及跨房间异步竞态。
- Playwright `im-daily-use.spec.ts` 覆盖桌面/移动端刷新恢复、发送清理、群聊切换和单聊复用。

## 未包含

- 多人送达/已读回执、外部推送、在线状态与输入中状态留待公开多用户阶段。
