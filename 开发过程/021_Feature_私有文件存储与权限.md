# 021 Feature - 私有文件存储与权限

> 日期：2026-08-10  
> 范围：IM-1 第 1 阶段

## 背景

IM 文件不能放进 `public/`，也不能依赖拿到 URL 即可访问。文件必须和工作区、房间、上传者、消息及 Agent run 的当前权限一起判断。

## 关键决策

- 采用前向迁移 `007_im_resources.sql` 和 `008_attachment_filename_constraint.sql`，不修改已应用迁移。
- 二进制存入私有 `BlobStore`，数据库只保存不透明 object key；浏览器和 Agent 均看不到物理路径。
- 上传流式计算 SHA-256、识别媒体类型并限制大小；下载支持 Range，避免整文件进入应用内存。
- pending、ready、failed 状态显式持久化；重复请求走幂等键，失败不伪装成功。
- 每次元数据或字节读取都重新检查 Principal、工作区、房间、消息和当前成员关系。

## 否掉的备选

- 放入 `public/` 或永久签名 URL：撤权后仍可能被旧链接读取。
- 把文件字节存进消息或 PostgreSQL：消息查询与大文件耦合，也不利于后续对象存储迁移。
- 仅靠前端隐藏下载入口：不能形成安全边界。

## 验证结果

- BlobStore 单元测试覆盖路径穿越、Range、大小上限、中断流和清理。
- PostgreSQL/HTTP 集成覆盖上传所有权、跨房间/工作区拒绝、幂等链接、媒体识别和私有字段不泄露。
- 空库及既有迁移账本升级路径均由迁移套件验证。

## 未包含

- 生产对象存储、病毒扫描、法律保留和公开分享链接不在 V0.9。
